## 0. GLOBAL RULES — READ BEFORE ANY WORK. THESE OVERRIDE EVERYTHING BELOW.

### 0.1 Commit authorship & attribution (MANDATORY, ZERO EXCEPTIONS)

1. **All commits are authored solely by the repository owner's git identity.** Before your first commit, run `git config user.name` and `git config user.email` and confirm they show the repo owner's human identity (currently `Vincent Naples`). If they show anything else, stop and notify the human operator.
2. **Never add attribution trailers or generated-by markers.** Specifically forbidden in commit messages, PR titles, PR bodies, code comments, docs, changelogs, and file headers:
   - `Co-Authored-By:` trailers of any kind
   - `Generated with`, `Generated by`, `Assisted by`, `Written by AI`, or similar
   - Any mention of an LLM, AI assistant, language model, chatbot, or the words **Claude, Anthropic, Gemini, OpenAI, GPT, Copilot, ChatGPT** — anywhere in the repository, in any file, in any commit message, ever.
3. **Pre-commit self-check (run before EVERY commit):**
   ```bash
   git diff --cached | grep -iE 'claude|anthropic|gemini|openai|gpt|copilot|co-authored|generated (with|by)|llm|a\.i\.|language model' && echo "VIOLATION - FIX BEFORE COMMIT" || echo "clean"
   ```
   If this prints `VIOLATION`, remove the offending text before committing. Also visually inspect your drafted commit message against the same list.
4. Commit messages use plain conventional style: `feat: ...`, `fix: ...`, `refactor: ...`, `test: ...`, `chore: ...`, `docs: ...`. One logical change per commit. No emoji, no footers.

### 0.2 Branch & merge discipline

- Canonical branch: **`main`** in this repository (`portal-dev`). This is the single source of truth; the fork-reconciliation merge already landed as `03b7aa5`.
- Each team works on its own branch: `sprint<N>/<team>-<topic>` (e.g. `sprint1/team-a-decompose`). Never commit directly to `main` except Sprint 0 hygiene.
- Rebase on `main` before opening a PR. Merge only when your sprint's smoke test (below) passes on your branch.
- Never force-push `main`. Never rewrite published history.

### 0.3 File-ownership rule (how parallel work stays conflict-free)

Each sprint below has an **Ownership Matrix**. A team may only modify files in its owned paths. If a task seems to require touching another team's file, stop and leave a note in `sprintboard.md` under a `## Cross-team requests` heading instead — the other team picks it up. `package.json` changes are allowed to any team but must be a separate commit titled `chore: add <package> for <purpose>` to keep merges trivial.

### 0.4 Universal Definition of Done (applies to every task)

- `npm run build` succeeds with zero errors.
- `npm run lint` passes (no new warnings on files you touched).
- Once Sprint 1 lands tests: `npx vitest run` passes.
- The attribution grep (0.1.3) is clean.
- `sprintboard.md` updated with a one-line entry: date, branch, what shipped.

### 0.5 Test-and-commit cadence

Commit at every **⛳ COMMIT POINT** marked below — these are placed immediately after a verifiable check. Never batch multiple ⛳ points into one commit. If a check fails, fix it before committing; never commit red.

### 0.6 Secrets

Never commit: `.env*` (except `.env.example`), `client_secret.json`, service-account JSON, any `FIREBASE_PRIVATE_KEY` value, any database secret. If you need a credential, reference it by env-var name and add the name (no value) to `.env.example`.

## 7. Cross-Sprint Reference

### 7.1 Escalate to the human (never guess) when…

- Any Google/Firebase console, domain, DNS, billing, or Workspace Admin action is needed (see HUMAN lists; also RTDB **Blaze plan upgrade** — required before any event with >100 simultaneous users, per strategy §4.6).
- A credential is missing, invalid, or found committed.
- A smoke-test step needs a second physical device, a cold email inbox, or a real phone.
- Two teams need the same file and the Ownership Matrix doesn't resolve it.
- Anything would delete data in the production Sheet, RTDB, or a Google Group.

### 7.2 Standing decisions (do not re-litigate)

- RTDB is runtime truth; Sheets is authoring; CSV is disaster mode (§4.4).
- The spreadsheet remains the admin panel — do not build event-editing UI (§10.12).
- `.ics` Tier 1 is required, not optional (§8.2).
- All RTDB writes stay `false` except the narrow, validated paths introduced in Sprints 2–3 (`admin-data/entries`, `user-data/$uid`) and reviewed token storage.
- Naming: `event-*`, never `festival-*`, in all new code.

1. Does the diff build? (`npm run build`)
2. Do tests pass? (`npm run test`, Sprint 1+)
3. Attribution grep clean? (rule 0.1.3)
4. Commit message: conventional prefix, describes the change, no trailers, no tool/vendor names?
5. Author identity = repo owner's?
6. Only files inside your Ownership Matrix paths?
